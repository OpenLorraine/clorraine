# Testing Strategy: Zero-Defect Closeout

> **Document**: 07-testing-strategy.md
> **Parent**: [Index](00-index.md)

## Testing Overview

| Code type | Target |
|---|---|
| Ownership/drop/loan changes | 100% of the row reproductions plus safe controls; ASAN/LSan clean |
| Null/narrowing/type rules | The reproduction and the concrete twin parity |
| Emission/ABI changes | Valid strict C and byte-identical re-emission where pinned |
| Resolution/diagnostics | The exact code, count, span, and help text |
| Regression surface | Full `make check` and `make verify` at every phase close |

- One ST case per row, grouped in six new spec/impl pairs:
  `def_zero_critical_*`, `def_zero_null_*`, `def_zero_calls_*`,
  `def_zero_loans_*`, `def_zero_emission_*`, and
  `def_zero_initializers_*`.
- The roadmap row owns the exact reproduction and its recorded evidence. The
  executor expands it into the test source; the expected column below is the
  frozen-spec/concrete-twin outcome. A code, count, span, or value named in the
  row is the oracle.
- A stale row is a green HEAD pin in Phase 0, not an ST red case.

## Red-Phase Rule

Every ST case is red on its phase's fix base before the implementation task.
A stale close records the HEAD command and its accepted result instead. No
green-before-red case enters the phase verdict.
