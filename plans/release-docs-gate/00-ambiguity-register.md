> **Last Updated**: 2026-11-27 19:13
> **Source**: user request after the v1.3.0 release: "a non negotiable check and flow … do a deep check and update the docs website for each release, like the project status, project brief, and such"

### Scope baseline

- **Planning target:** a release gate for documentation: an automated checker
  (`make release-docs-check VERSION=X.Y.Z`, static before the tag and `--live`
  after the site deploys), a committed human review record per release, the
  `RELEASE.md` flow and the `AGENTS.md` rule; proven by a real run against
  v1.3.0.
- **Context artifacts:** `RELEASE.md`, `AGENTS.md`, `Makefile`, `site/`,
  `README.md`, `docs/`, `RELEASE-NOTES.md`, `CHANGELOG.md`, `tools/vscode/`,
  `tools/setup/` (test conventions), `plans/vscode-marketplace-v1.3.0/`.
- **Modification set:** new `tools/release/` (checker, manifest, tests), new
  `docs/release-reviews/` (template, v1.3.0 record), `Makefile`, `RELEASE.md`,
  `AGENTS.md`, `plans/00-roadmap.md`, and the release-facing files above only
  where the v1.3.0 proof run finds a real defect.
- **Mode:** `--auto-design` (eligible technical decisions delegated and
  recorded), `--auto-commit` (commits pushed to `main`); strict scope.
