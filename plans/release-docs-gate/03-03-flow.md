## Make and CI (AR-27, AR-29)

- `release-docs-check`:
  `python3 tools/release/docs_check.py --version "$(VERSION)" $(if $(LIVE),--live) $(if $(TODAY),--today $(TODAY))`.
  `VERSION` defaults to the Makefile's Cargo version, so `make release-docs-check` alone checks the version in the tree.
- `release-docs-test`:
  `cd tools/release && PYTHONPATH=tests python3 -m unittest docs_check_spec docs_check_impl -v`.
  Added to `check` after `dist-check`, and as a step in `.github/workflows/check.yml`.
- `release-docs-check` is not part of `check` or `verify` (AR-29, AR-31).

## Review template (AR-33)

The template is `docs/release-reviews/TEMPLATE.md`. It opens with a short note on who signs (AR-10), then the two sections below.

`## Before tag`
- Status page: one row per supported platform; what works / not ready; release state and license name this release
- Project brief: header, Status row, Roadmap and Next match this release
- Roadmap page: Delivered and Next match this release
- Known limitations: site and docs/ say the same and match this release
- Quick start matches the real installer prompts and `--help` on every platform
- Home page, preview bar, sidebar and README show every platform's install command for this release
- No single-platform wording where more platforms are supported
- Screenshots and the social card still match the product
- Extension README and CHANGELOG are current (they ship in the extension; this is the last chance before it is published)
- Latest-stable and preview wording is correct for this release
- Every allowlist change was read and its reason is true
- The local preview build (`make site-dev`) was walked page by page

`## After deploy`
- `make release-docs-check VERSION=X.Y.Z LIVE=1` passed
- The published GitHub release body was read
- The live home page, quick start, and both install commands were read

## RELEASE.md (AR-8, AR-10, AR-15, AR-24, AR-31)

- **Step 2 (Version):** add the docs sweep. Copy the template to `docs/release-reviews/vX.Y.Z.md`. Agents prepare it; ticks and `Reviewer` are written only after the maintainer confirms.
- **Step 3 (Gate):** `make verify` **and** `make release-docs-check VERSION=X.Y.Z` on the release commit. The tag waits for both.
- **Step 11 (Check):** after the docs deploy run succeeds, tick `After deploy` in a commit on `main` and run `make release-docs-check VERSION=X.Y.Z LIVE=1`. On exit 4, wait for the deploy and retry once after 10 minutes. On exit 3, rerun later; there is no override.
- **Step 12 (Close out):** waits for a passing live run. The announcement, issue closing and any move to Latest come after it.
- **"When a step fails":** add the fix-forward rows for site, README and docs, the release body, and VSIX-shipped files or asset content.

## AGENTS.md (AR-8, AR-10)

Add one bullet under the CodeOps section, plus the two targets in the Commands table:

> Every release passes `make release-docs-check VERSION=X.Y.Z` before the tag and with `LIVE=1` before close-out (announcement, closing issues, any move to Latest), per `RELEASE.md`; no override. Agents may prepare `docs/release-reviews/vX.Y.Z.md` but tick it and fill `Reviewer` only after the maintainer confirms.

## docs/README.md (AR-30)

Link `release-reviews/` (the folder), not individual records.
