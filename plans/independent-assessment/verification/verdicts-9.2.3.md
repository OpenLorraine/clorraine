## New finding (for verification by a different session)

### ASM-WS3-008 — An `else if` chain of 127 or more arms makes vbcc crash or reject the emitted C

- **Severity**: Major
- **Confidence**: verified
- **Lens**: vbcc leg of hosted-amiga (`vc +aos68k -c99 -O2 -cpu=68000`). The m68k GCC and host legs accept the same unit.
- **Location**: structured `if` emission in `compiler/src/codegen/control.rs:421-442` (`emit_conditional` prints `if (…) {` … `} else {` and emits the false branch recursively inside the `else` block), at e24a8752
- **Checklist item**: WS3-11
- **Author session**: ses_dea9a6112ffeMR984F2rpPTplg
- **Evidence**: Reproduction with `build/tmp/assessment/verify/9.2.3/vbcc-nest.sh`, command `make -C docker exec CMD="bash build/tmp/assessment/verify/9.2.3/vbcc-nest.sh"`. It generates `func f(n: i32): i32` containing `if (n == 0) { r = …; } else if (n == 1) { … } … else { r = -1; }` with N arms, emits it for hosted-amiga with the pinned clc, and compiles it with vbcc and m68k GCC (`-O2 -c`). clc accepts every N.
  - Observed with vbcc: N = 100, 124, 125, 126 compile.
  - N = 127: vbcc ends with `Segmentation fault (core dumped)`.
  - N = 128: `error 9 … too many (128) nested blocks`; N = 500 and N = 1,000 fail the same way.
  - m68k GCC compiles every N.
  - The emitted C nests one block per arm: `} else {` / `#line …` / `if ((n == 2)) {` …
  - A control with 127 nested plain source blocks `{ { … } }` compiles, because plain blocks are flattened.
  - C99 §5.2.4.1 guarantees only 127 nesting levels of blocks. A function body plus 126 `else` blocks plus the innermost `if` block already reaches 128, so the emitted C exceeds the C99 minimum translation limit from 127 arms.
- **Impact**: a program with a long `else if` dispatch (a command parser, an opcode or key table written as `else if`) cannot be built on the vbcc leg: vbcc crashes at 127 arms and refuses from 128. The GCC legs are unaffected, and the failure is at build time (no wrong binary).
- **Root cause**: the emitter nests every `else` arm inside a new C block instead of emitting the C `else if` form (`} else if (…) {`) or a flat `goto`-based chain, so the C nesting depth grows linearly with the arm count.
- **Recommendation**: when the false branch of a conditional is itself a single conditional with no hoisted declarations or cleanup, emit `} else if (cond) {` at the same depth. Otherwise, past a fixed depth, fall back to the existing `goto` form (`if (c) goto T; else goto F;`, `control.rs:415`). Add a vbcc build golden with a 200-arm `else if` chain.
- **Effort**: S
- **Related**: ASM-WS3-007 (vbcc `switch` scaling: this blocks the if-chain workaround for it); ASM-WS1-004 (`clc` overflows at 4,310 arms); `docs/known-limitations.md` lists vbcc limits for the bsdsocket headers only.
