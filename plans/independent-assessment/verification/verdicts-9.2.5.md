## WS8-003 / ASM-WS2-003 decision

**Narrow ASM-WS8-003 to causes (2)–(4). Cite ASM-WS2-003 for cause (1) and do not count it again in the ranked list.** Both alternatives are worse:

- A full merge into ASM-WS2-003 would lose the three causes WS2-003 does not cover: string-composed C (invalid C: ASM-WS3-001/-002), route-specific checks (false accepts: ASM-WS1-005, ASM-WS2-002), and effects left inside unsequenced C expressions (miscompile: ASM-WS1-002). Each has its own DEF-class evidence (118/100/51 rows) and its own remedy (typed C tree, a normalized check form, A-normal form).
- An umbrella that restates cause (1) would rank the same defect twice: the same `needs_drop` (`codegen/drop.rs:283`) versus `maybe_owns_ty` (`own.rs:675`) split, the same sites, and the same "ownership stage as the single authority" remedy.
- After narrowing, WS8-003's recommendation keeps its ANF and typed-C-printer parts. The "codegen emits only recorded drops" sentence moves into a pointer: "together with ASM-WS2-003's single drop authority".

## Other merges and duplicates

- ASM-WS7-001 and ASM-WS4-004 stay separate (fill path versus template-`memcpy` path) but should cross-reference each other. Both come from module initializers lowered as run-time stores rather than static data.
- ASM-WS5-023 stays separate from ASM-WS5-016 (read hang versus raw-data semantics). ASM-WS8-002's gate citation (`clip: ok n 4` is a constant label) supports it.
- ASM-WS3-008 stays separate from ASM-WS3-007 (vbcc time on `switch` versus vbcc block-nesting limit on `if` chains). Both limit the vbcc leg on large dispatch code.
- ASM-WS7-002: add `compiler/src/codegen.rs:1009-1020` (the `resolve_function` linear fallback) to its location instead of raising a separate finding. It is the same cost class and the same remedy (a name index).
