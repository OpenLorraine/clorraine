# Design: installer, candidate archive, acceptance

> **Requirements**: R1–R3, R12–R14, Q4–Q7
> **Evidence**: glibc and toolchain pins in `spikes/07-linux-cli-fs-uae/README.md`

## Candidate assets

`make dist VERSION=1.2.0` builds release binaries in the pinned development
container and writes only local files under `build/dist/`. The build baseline
is the SDK image (Debian bookworm, glibc 2.36), not Ubuntu 24.04: building the
CLI on a newer glibc would raise its own floor above the documented 2.38.
`make dist` uses `make -C docker exec CMD="cargo build --release --workspace"`
and fails with the documented `make -C docker image` action when the image is
missing, rather than silently using a different host. Docker is a maintainer
build dependency here, not a user install dependency: `install.sh` never
invokes Docker.

Assets:

```
clorraine-1.2.0-x86_64-linux.tar.gz
clorraine-1.2.0.vsix
install.sh
SHA256SUMS
```

`SHA256SUMS` covers the archive, the VSIX, and `install.sh`. `make dist-verify`
checks all three against the current bytes.

`make dist` first validates `VERSION` against `compiler/Cargo.toml` and
`tools/vscode/package.json`, then runs `bin/clorraine --version` from the built
tree. A mismatch fails before packaging. The VSIX is produced by
`make vscode-package`; Node.js/npm is a maintainer build dependency, not a user
install dependency.

Archive root and contents:

```
clorraine-1.2.0-x86_64-linux/
  bin/clc
  bin/clorraine
  bin/clorraine-lsp
  README.md
  LICENSE
  LICENSE-EXCEPTION.md
  NOTICE
  THIRD_PARTY_NOTICES.md
```

The archive README and notice are release-specific files generated by the
packaging script. They use release URLs for repository-only references, so no
link points at `docs/`, `spec/`, `docker/`, or `tools/` paths that are absent
from the archive. The archive contains no toolchain, ROM, FS-UAE binary, Python
helper, or licence-restricted media.

The VSIX is a separate local artifact from `make vscode-package`
(`build/dist/clorraine-1.2.0.vsix`), not a file inside the CLI archive. It is
installed with `code --install-extension`; marketplace or release publication is
out of scope for this plan.

`make dist` does not tag, create a release, or upload. Publication is a separate
approval.

## Installer contract

```
install.sh [--prefix DIR] [--modify-path]
           [--archive FILE --checksums FILE] [--uninstall [--purge]]
```

Default prefix: `$HOME/.local`. The installed version is compiled into the
release script; there is no version-selection flag.

### Host checks

| Check | Failure |
|---|---|
| `uname -s` is Linux | exit 1, "Linux x86_64 is required" |
| `uname -m` is `x86_64` | exit 1, "Linux x86_64 is required" |
| `getconf GNU_LIBC_VERSION` reports glibc >= 2.38; a failed/non-glibc result is rejected | exit 1, "Clorraine 1.2.0 needs glibc 2.38+ (Ubuntu 24.04+); found X" |
| `--prefix` is absolute and writable (or creatable) | exit 1, names the prefix and the permission |
| Required commands exist | exit 1, lists missing commands and a package hint |

Always required: `uname`, `tar`, `gzip`, `sha256sum`, `getconf`, `mktemp`,
`awk`, `sed`, `grep`, `find`, `wc`, `basename`, `dirname`, `sort`, `ln`, `mv`,
`rm`, `mkdir`, `cp`, `chmod`. `curl` is required only for network mode;
`--archive/--checksums` works offline without it.

The 2.38 floor comes from the rc24 toolchain, not the CLI (built on bookworm
glibc 2.36). The product path needs the toolchain, so the installer checks it
before any downloaded CLI runs.

### Network mode

The assembled script contains:

```
VERSION=1.2.0
ARCHIVE_NAME=clorraine-1.2.0-x86_64-linux.tar.gz
ARCHIVE_URL=https://github.com/OpenLorraine/clorraine/releases/download/v1.2.0/clorraine-1.2.0-x86_64-linux.tar.gz
ARCHIVE_BYTES=<exact>
ARCHIVE_SHA256=<64 hex>
```

It downloads with:

```
curl --disable --fail --location --proto '=https' --proto-redir '=https' \
  --connect-timeout 20 --max-time 600 --max-filesize <bytes+1> \
  --output <private archive>
```

It verifies the exact byte count and SHA-256 before extraction. `--disable`
prevents a user curlrc from disabling certificate checks. No response body is
piped to a shell or interpreter.

Network mode is for a published release. The candidate acceptance uses
`--archive/--checksums`; the `ARCHIVE_URL` is assembled for the future
publication and must not be exercised before separate approval.

### Local candidate mode

`--archive FILE --checksums FILE` is the offline path used by acceptance. It
selects exactly one checksum line for `basename(FILE)`, computes the archive
digest directly, and compares:

```
expected=$(awk -v n="$base" '$2 == n { print $1; count++ } END { exit count == 1 ? 0 : 1 }' "$checksums")
actual=$(sha256sum "$archive" | awk '{ print $1 }')
[ "$actual" = "$expected" ]
```

It records the byte count as evidence but does not require the release-pinned
byte count, so exact draft bytes with a different size can be tested. It never
downloads. Missing, duplicate, or malformed lines are errors. This is the
documented way to test draft bytes and is not a URL or hash bypass.

### Install and activation

With `PREFIX`:

1. Resolve `PREFIX` to an absolute path; reject control characters, newlines, and `:` (the PATH separator).
2. Create `PREFIX/share/clorraine` and acquire the lock (below).
3. List archive member types and reject absolute paths, `..` components,
   symlinks, hardlinks, devices, and FIFOs. The pinned hash is the primary
   integrity boundary; this check is defense-in-depth.
4. Require exactly one top-level archive directory and no top-level files;
   extract into a private `PREFIX/share/clorraine/.tmp.<pid>` with
   `--strip-components=1 --no-same-owner --no-same-permissions`.
5. Verify the expected `bin/` and doc files exist directly under the temporary
   directory and are ordinary files or directories.
6. Run `bin/clorraine --version` and require `1.2.0`.
7. Move the tree to `versions/1.2.0-<archive-sha12>`. If that directory already
   exists, verify it and reuse it; never move the old `current` target.
8. Remove any stale `current.new`, create
   `current.new -> versions/1.2.0-<archive-sha12>`, and atomically rename it over
   `current`. The old `current` remains usable until this rename.
9. Create or replace `PREFIX/bin/{clc,clorraine,clorraine-lsp}` symlinks to
   `../share/clorraine/current/bin/<name>`, but only when they are absent or
   already point into this Clorraine prefix. A foreign file at that name is an
   error and is never overwritten.
10. On a handled failure, restore the previous `current`, remove any
    `PREFIX/bin` symlinks this invocation created, and leave the installed old
    version usable. A crash before the `current` rename leaves the old target
    untouched; the hidden `.tmp.<pid>` directory is inert.
11. Remove the private tree and release the lock.

Cross-version updates keep the old `versions/<version>-<sha12>` directory.
`current` points at the new unique directory; no old tree is moved.

### Lock

The lock is `PREFIX/share/clorraine.lock`, a sibling of the purge target, created atomically with `mkdir`.
It contains `pid` and the process start time from `/proc/<pid>/stat` field 22.
A lock is stale when the PID is absent or its start time differs. The installer
removes a stale lock and retries `mkdir` once; a second concurrent winner is an
error naming the owner. Live locks fail immediately. Install and uninstall take
the same lock. Tests cover live, stale, and concurrent installers.

### PATH

Without `--modify-path`, the installer prints the exact `PATH` line to add.
With `--modify-path`, it resolves the prefix and replaces one marked block in
`$HOME/.profile`. The prefix is single-quote escaped with the POSIX `'\''`
idiom, and the PATH test uses a variable expansion inside a double-quoted case
pattern:

```
# >>> clorraine >>>
clorraine_bin='<single-quoted-prefix>/bin'
case ":$PATH:" in *":$clorraine_bin:"*) ;; *) PATH="$clorraine_bin:$PATH";; esac
export PATH
# <<< clorraine <<<
```

A prefix containing `:` or a control character is rejected; `:` would corrupt
PATH, and control characters cannot be represented safely. Spaces, single
quotes, `$`, backticks, and glob characters are handled by the single-quoted
assignment. If a marked block already exists it is replaced, not duplicated.
Existing shells must source the profile or open a new shell. `--uninstall`
removes the marked block. Tests cover spaces, a single quote, a glob character,
replacement, and removal.

### Config path and uninstall

The installer resolves the config directory exactly as the CLI does:

1. `$XDG_CONFIG_HOME/clorraine` when `XDG_CONFIG_HOME` is absolute.
2. Otherwise `$HOME/.config/clorraine`.
3. File: `.../config`.

`--uninstall` removes `PREFIX/bin/{clc,clorraine,clorraine-lsp}` only when each
symlink points into `PREFIX/share/clorraine`, removes `current`, and removes the
PATH block. It keeps `versions/` and the config directory.

`--purge` additionally removes `PREFIX/share/clorraine` and the resolved config
file; it removes the config directory only if it is empty. No user source, build
output, toolchain, ROM, or unrelated config is deleted.

## Make targets

| Target | Contract | In `make check`? |
|---|---|---|
| `make dist` | Build binaries + VSIX, stage release docs, package archive/checksums, assemble installer | No |
| `make dist-verify` | Check pins, versions, asset hashes, and forbidden archive contents | No |
| `make dist-check` | Hermetic producer + installer tests with fixture trees and fake tools | Yes |
| `make acceptance` | Fresh temporary HOME + local candidate + verified `TOOLCHAIN_ARCHIVE` + FS-UAE; writes evidence JSON | No |
| `make acceptance-check` | Validate an evidence JSON against the candidate and expected corpus bytes | No |
| `make vscode-package` | Build and audit the local VSIX | Via `make vscode-check` |

`dist-check` must not need network, Docker, a toolchain, a ROM, FS-UAE, or the
real release archive. It uses fixture stage trees, a fixture archive, fake
`uname`, `getconf`, `curl`, and `sha256sum`, and a PATH missing selected
commands. Production still invokes the real tools with literal argv.

The installer tests use a fixture archive with the same versioned top-level
directory as `make dist`, so `--strip-components=1` and the final `current/bin`
layout are exercised.

Producer tests (`tools/setup/tests/dist.spec.test.sh`) run the packaging script
on fixture inputs and assert:

- the exact archive layout and no forbidden files;
- a version mismatch fails;
- an extra file fails `dist-verify`;
- a stale installer pin fails `dist-verify`;
- `SHA256SUMS` covers archive, VSIX, and installer;
- release README/notice relative links resolve inside the archive.

## Acceptance evidence

`make acceptance CANDIDATE=... TOOLCHAIN_ARCHIVE=... KICKSTART=...` records:

```json
{
  "version": "1.2.0",
  "platform": "linux",
  "architecture": "x86_64",
  "glibc": "<actual>",
  "archive": {"name": "...", "sha256": "...", "bytes": 0},
  "installer": {"sha256": "..."},
  "vsix": {"name": "...", "sha256": "...", "bytes": 0},
  "toolchain": {"tag": "v16.2-rc24", "sha256": "...", "bytes": 0},
  "kickstart": {"name": "...", "sha256": "..."},
  "fs_uae": "3.2.35",
  "guest": {"status": "ok", "rc": 0, "output": "...", "output_sha256": "..."},
  "negative": {"status": "failed", "rc": 1},
  "corpus": [
    {"name": "file-copier", "profile": "hosted-amiga", "status": "ok", "output_sha256": "..."},
    {"name": "string-parser", "profile": "hosted-amiga", "status": "ok", "output_sha256": "..."},
    {"name": "buffer-container", "profile": "hosted-amiga", "status": "ok", "output_sha256": "..."},
    {"name": "volatile-mmio", "profile": "hosted-amiga", "status": "ok", "output_sha256": "..."},
    {"name": "file-copier", "profile": "hosted-amiga-13", "status": "ok", "output_sha256": "..."}
  ],
  "timestamp": "..."
}
```

`acceptance-check EVIDENCE=... CANDIDATE=...`:

- hashes the candidate archive, installer, and VSIX and compares them;
- requires `version=1.2.0`, `platform=linux`, `architecture=x86_64`, `glibc>=2.38`;
- requires the exact rc24 tag, byte count, and SHA-256
  (`b93b070a…25c100`, `69,868,548` bytes);
- requires FS-UAE >= 3.2.0;
- requires the exact hello output
  `Hello, Amiga, from Clorraine!` and its hash;
- requires the four `hosted-amiga` corpus entries plus one
  `hosted-amiga-13` corpus entry, each `status=ok` and each output hash equal
  to the normalized `spec/tests/corpus/<name>/expected-output.txt` bytes;
- requires the rc-1 negative record to show `status=failed` and a nonzero `rc`;
- rejects a non-`ok` status or nonzero `rc` for success records.

Negative tests cover a wrong toolchain tag/hash, an older FS-UAE, wrong hello
output, a wrong corpus hash, a missing VSIX, and a candidate-hash mismatch.

Acceptance uses an isolated `HOME`, installs with
`install.sh --archive ... --checksums ...`, verifies the supplied
`TOOLCHAIN_ARCHIVE` directly against the pinned rc24 hash, extracts it into a
private root, runs `setup --toolchain` with that root,
builds hello and the corpus, and runs each through the real FS-UAE with the
licensed KS3.1 A1200 ROM. It uses `xvfb-run -a` when the host has no display, and after each guest run
asserts that no `fs-uae` or `Xvfb` process from that run remains. The raw
output, hashes, and commands are kept under `build/acceptance/`.

The checker does not download anything and does not contact GitHub.

## Publication boundary

No step in this plan creates a tag, release, or upload. The candidate is a
local build artifact. After acceptance, publication needs a separate user
approval and a release plan.
