# Box Design: `Box<T>`

> **Document**: 03-01-box.md
> **Parent**: [Index](00-index.md)
> **Requirements**: R1-R6

## 1. Type model

`Box<T>` is a new checked type shape:

```rust
TyKind::Box(Box<Ty>)
```

The type carries its element, so every later stage can name it without a side
registry. The C form is `void *`; the target size is the pointer size; the
empty state is `NULL`.

Resolution order in `resolve_named` (`compiler/src/types/table.rs:798-823`):

1. a type parameter;
2. a declared struct (a user `struct Box<T>` is rejected before this point by
   the reserved-name rule);
3. `String`;
4. a declared handle;
5. a declared enum;
6. the built-in `Box` with exactly one type argument;
7. `Unknown`.

The resolve stage runs before the type table (`compiler/src/resolve/mod.rs:65-88`)
and predeclares only `String` today (`resolve/mod.rs:465-470`). It must
predeclare `Box` as a **type-only** name in `resolve_type_name`, so the
standard library's own `Box<T>` signatures resolve; `Box` must not be a new
keyword. A user declaration named `Box` shadows the built-in through the
ordinary order, exactly as a user `String` does: the standard-library
`boxNew`/`boxSet`/`boxWith` surface is then retyped and unavailable, which is
documented as a limitation. Reserving the name was rejected at execution
because it broke 957 existing implementation-test sources and the spec's own
`Box<T>` generic example.

The arity check is explicit because no declaration supplies it: `Box` with
zero or two or more arguments reports `E10300`. The argument itself is
validated by the ordinary type-argument walk, so `Box<i32?>` reports `E10011`
at the inner nullable scalar.

## 2. C representation and layout

| Position | C spelling |
|---|---|
| value, local, parameter, return | `void *` |
| struct field, array element | `void *` |
| null literal | `NULL` |
| `sizeof(Box<T>)` | target pointer size (4 on m68k, 8 on the host) |
| `type_key` | `__cl_box__<element key>`, with the usual `Q` nullable suffix |

`void *` is deliberate: the pointer is opaque to C, every cast back to `T *`
is an explicit raw cast inside the library, and the type cannot be confused
with a typed pointer at the ABI. The language type keeps `T`; no C typedef is
needed.

## 3. Allocation

Two runtime helpers are added to the host and hosted-amiga shims:

```c
void *cl_box_alloc(unsigned int size);   /* zeroed; traps on failure */
void cl_box_free(void *box);             /* null-safe */
```

`cl_box_alloc` uses `cl_alloc`/`cl_free` (host `malloc`/`free`; the Amiga C
runtime's allocator on both Amiga profiles) and zeroes the block with
`memset`. The zero state is the language's empty state (O7), so the first
store's old-value drop is a no-op for every owning `T`.

`boxNew<T>` is ordinary Clorraine in `std.mem` (no `export` marker: a generic
function cannot be exported; the export table covers it):

```clorraine
func boxNew<T>(take value: T): Box<T> {
    let b = boxAlloc<T>();
    unsafe { *boxPtr<T>(b) = value; }
    return b;
}
```

The intrinsic `boxAlloc<T>()` lowers to `cl_box_alloc__<key>()`, a generated
`static inline` helper returning `cl_box_alloc(sizeof(T))`. The raw store moves
`value` into the block; the parameter's cleanup is a no-op after the move.

`boxAlloc` must be wired through every intrinsic layer:
`compiler/src/stdlib.rs` (`COMPILER_INTRINSICS`, so
`the_compiler_intrinsic_set_matches_the_library_declarations` passes; the
`load` E20006 check uses the same set), `sema/call.rs` (the free and qualified
call branches; a wrong type-argument count is `E10300`, a value argument is
`E10308`), `own/lower.rs` (the `cl_box_alloc__<key>` call), and
`codegen/calls.rs` (an explicit emission arm; the current fallback is a silent
`0`). It is not added to `RESERVED_BUILTINS`, because that list drives the
parser's intrinsic-call spelling and `boxAlloc<T>()` is an ordinary generic
call node. `Box` is added to `COMPILER_KNOWN_EXPORTS` so the table's `Box`
export passes `every_export_is_declared_or_compiler_known`; `boxAlloc` is not
exported in the import table.

An allocation failure keeps the existing `cl_alloc` contract: it prints
`error E1: out of memory` and aborts. `boxNew` is therefore non-nullable and
`Box<T>?` is an optional slot, not an allocation result.

## 4. Replacement and access

```clorraine
func boxSet<T>(borrow b: Box<T>, take value: T): void {
    unsafe { *boxPtr<T>(b) = value; }
}

func boxWith<T, F: func(T): void>(borrow b: Box<T>, f: F): void {
    unsafe { f(*boxPtr<T>(b)); }
}

func boxPtr<T>(borrow b: Box<T>): raw T {
    unsafe { return raw T(b); }
}
```

`boxWith` relies on the checker's parameter matcher recursing into
`TyKind::Box`: `T` binds from `b: Box<T>` and `F` binds from the capturing
lambda. Without that arm, the call reports `E10301` because `T` occurs only
under `Box`; the explicit `boxWith<String, func(String): void>` spelling is not
a substitute because a capturing lambda does not convert to a concrete
`func(...)`. A `Box<T>` argument is spelled by value (`void *`), not as a
pointer-to-pointer: `is_pointer_param` must keep returning false for Box. The
raw cast of a `Box<T>` operand is accepted only in `std.mem`; an application
`raw T(b)` is `E10201`, so application code cannot move the pointee out or
free it.

- `boxSet` relies on the existing raw-store rule: a store through a
  dereferenced raw pointer releases the replaced owning pointee exactly once.
  That rule is already pinned by
  `conditional_projection_residue_spec_test::should_release_the_replaced_owning_pointee_of_a_raw_store`.
- `boxWith` passes a read-only lend of the pointee. A duplicable `T` copies; a
  move-only `T` borrows. The callback returns `void`, so a view derived from
  the pointee cannot escape. A capturing lambda is accepted through the
  ordinary callable-bound path, because `boxWith` is a synchronous Clorraine
  call.
- `boxPtr` is module-private. Application code cannot obtain a raw pointer to
  the boxed storage, so it cannot free it or move the value out.

## 5. Drop glue

`needs_drop(Box<T>)` is true: the type is not duplicable, not a view, not a
parameter, and not void. The drop emitter adds one arm before the struct/array
arms:

```text
Box<T>:
    if (b) { cl_box_drop__<element key>(b); }
    b = NULL;
```

The expression form used by guarded operands is:

```text
(b ? (cl_box_drop__<element key>(b), b = NULL) : 0)
```

The helper is generated once per used element type:

```c
static inline void cl_box_drop__i32(void *box)
{
    if (!box) { return; }
    /* drop of *(i32 *)box: nothing for a scalar */
    cl_box_free(box);
}
```

For a `T` with owned fields the middle line is the existing recursive walk
applied to the lvalue `(*(<T> *)box)`. That walk already handles:

- a handle field: `if ((*(S *)box).s) { FreeString(...); } ... = NULL;`
- a nested box: the inner `cl_box_drop__<key>` helper;
- a fixed array: one index level per extent;
- a growable `Array<T>`: the element loop, then the buffer drop;
- a struct: fields in declaration order.

The helper is `static inline`, which the shim already uses so an unused
definition does not trip `-Wunused-function` under `-Werror`. Helpers are
collected by the emitter's type walk across function signatures, locals,
temporaries, struct fields after instance substitution, fixed-array elements,
`Array` elements, and nested boxes. Every helper has a `static inline`
prototype before the first definition, because `A` holding `Box<B>` and `B`
holding `Box<A>` makes the two drop helpers mutually recursive; C99 requires a
declaration before a call. The `struct_units` ordering is not enough for a
cycle. Add an `A`/`B` mutual-recursion case to the suite.

`emits_drop` must also return true for `TyKind::Box`: the assignment path uses
it to decide whether to release the old target before storing. Without the arm
a reassignment (`b = boxNew(...)`) overwrites the old pointer and leaks the
block and its pointee.

The storage is freed only after the pointee drop. A null box returns
immediately. The caller's box is nulled after the helper, so a second drop is
a no-op.

## 5.1 Layout

`AbiLayout::size_at`/`align_at` and `TypeTable::size_of_at` gain a Box arm:
pointer size, pointer alignment. Without it, a struct containing a Box has an
unknown size, so `sizeof(StructWithBox)`, `offsetof(StructWithBox, field)`,
and an array extent written with either stop folding. The test matrix covers
all three, not just `sizeof(Box<i32>)` (which the emitter spells as
`sizeof(void *)` and does not consult the table).

## 6. Ownership, moves, and nullability

- `duplicable(Box<T>)` is false; assignment and argument passing move.
- `is_handle(Box<T>)` is true for the ownership classification ("an owning
  handle, whose value must be released"). It must **not** be used to spell a
  `borrow Box<T>` parameter: `is_pointer_param` keeps returning false for Box,
  so the parameter is the `void *` value, not a `void **`. A pointer-to-box
  spelling would make `boxPtr`'s `raw T(b)` point at the box slot rather than
  the heap block.
- `is_lend_candidate(Box<T>)` is true; a box owns storage a returned view could
  derive from, so it participates in elision like a handle.
- `is_nullable_capable(Box<T>)` is true; `Box<T>?` is an optional slot.
- `is_view(Box<T>)` is false; `is_whole_slot_view` is false.
- `embeds_by_value(Box<T>)` is false; a struct may hold `Box<Node>?`.
- `contains_param`, `substitute`, and `mentions_type_param` recurse into the
  element.
- `contains_closure`, `mentions_heap_string`, `mentions_unbound`, and
  `record_struct_type` recurse into the element; their current `_ => false`/`_
  => {}` fallbacks silently miss `Box<closure>`, `Box<String>` on
  freestanding, a `Box<T>` parameter in a generic call, and a
  `Wrap<i32>` nested inside a Box.
- A raw cast whose operand is a `Box<T>` is rejected outside `std.mem`
  (`E10201`); `boxPtr` is the library's sanctioned spelling.

## 7. Generic arguments

`Box<T>` is a storable aggregate. The ordinary generic checks apply:

- `Box<Box<String>>` is a box of a box; each layer has its own helper.
- `Box<Struct>` / `Box<Array<i32>>` recurse through the existing drop walk.
- `Box<raw T>` / `Box<func(i32): i32>` are pointer-sized elements with no
  drop; accepted.
- `Box<closure>` is `E10306` (ephemeral type argument to a storable
  aggregate).
- `Box<str>` / `Box<cstring>` / `Box<u8[]>` are `E10227` (a boxed view could
  outlive its origin).
- `Box<Overlay>` is `E10207` (overlay values describe memory the program does
  not own).
- A generic body may write `Box<T>`; each instantiation substitutes and the
  monomorphization key uses the `__cl_box__<element key>` type key.

## 8. FFI crossing

A `Box<T>` parameter or return type in an `ffi` declaration reports the new
`E10105`:

```text
error E10105: 'Box<i32>' cannot cross the FFI boundary
help: pass the pointee through `boxWith`, or a raw pointer from an unsafe wrapper
```

The same check rejects any generic struct instance anywhere in an `ffi`
signature (including inside a callback's function-pointer type), because the
current emitter writes `ClWrap` while the typedef is `ClWrap__i32` (see
[Current State](02-current-state.md) section 5). The check runs in
`ffi::check_items`, which currently has no `TypeTable`; the caller
(`own.rs:286-287`) passes `&sema.table`, and each block's declaring module is
available from the module iteration. Each signature type is resolved with
`resolve_ty_folded`, not `resolve_ty`, so import aliases work. Interop goes
through `boxWith`.

## 9. Blast radius checklist

The new `TyKind` variant must be handled at every exhaustive match **and every
silent `_` fallback**; the Rust compiler only confirms the former. The plan
walks this list once and pins the important ones with tests:

| Area | Sites |
|---|---|
| Resolve | `resolve/mod.rs:431-470` type-only `Box` predeclaration; reserved-type-name rejection |
| Type model | `types/mod.rs` display, substitute, contains_param, is_param, nullable, view, `contains_closure`; `types/keys.rs` (add `Box` to `RESERVED_COMPONENTS`); `types/layout.rs` size/align; `types/table.rs` resolution, duplicable, size, `is_struct` |
| Semantics | `sema/expr.rs` member/index/call/overlay and raw-cast rejection; `sema/items.rs` nullable and type-argument walks, `E10227`; `sema/mod.rs` overlay, container, `mentions_heap_string`; `sema/call.rs` `match_param`, `mentions_unbound`, conversions, dot-call |
| Ownership | `borrow.rs` view/handle/nullable/elision; `own/place.rs`, `own/expr.rs`, `own/statements.rs`, `own/lower.rs`, `own/generics.rs` (`is_concrete`, `record_struct_type`), `own/instance_check.rs` |
| Codegen | `codegen/types.rs` C spelling and declarator (not `is_pointer_param`); `codegen/drop.rs` drop and `emits_drop`; `codegen/expr.rs` empty state, null, materialization; `codegen/program.rs` helper collection, prototypes, emission; `codegen/function.rs` statements; `codegen/calls.rs` `boxAlloc` arm |
| ABI | `abi.rs` total mapping (Box is rejected at FFI, but the mapping stays total); `ffi.rs` uncontracted classification and `E10105` |
| Constants | `consts` size/sizeof folding through `types/layout.rs`; `sizeof(StructWithBox)` and `offsetof` |
| Stdlib | `stdlib.rs` `SOURCES`/exports/`COMPILER_INTRINSICS`/`COMPILER_KNOWN_EXPORTS`; `token.rs` reserved names; `std.mem` API |

## 10. Rejected alternatives

| Alternative | Why rejected |
|---|---|
| Generic struct with a `BoxStorage` field | The language has no field privacy; safe code could move the storage between boxes of different `T` and type-confuse the drop |
| Synthetic handle name | Loses the element type for display and helper generation; needs a side registry |
| `raw T` field | Duplicable, so the box would not be move-only or droppable |
| Heap-allocated drop function pointer | Adds a heap environment and an ABI surface; unnecessary |
| Inline glue at every drop site | Code bloat; the recursive helper is one definition per element |
| Nullable allocation result | The allocator contract already traps; a nullable box would add an untested failure path |
