# Design: Amiga SDK Registry

> **Document**: 03-02-registry.md
> **Parent**: [Index](00-index.md)

## Purpose

The registry is the **source of truth** for the remaining Amiga SDK capabilities.
It is not an issue database and not a 1:1 NDK symbol list. Each row is a
capability with a stable ID, a baseline, a status, dependencies, and an acceptance
reference.

## Files

| File | Role |
|---|---|
| `docs/amiga-sdk/bundles.tsv` | One row per bundle: id, title, tier, min OS, min hardware, status, tracking issue, plan path |
| `docs/amiga-sdk/registry.tsv` | One row per capability |
| `docs/amiga-sdk/coverage.md` | Generated Markdown view; never hand-edited |
| `docs/amiga-sdk/README.md` | Schema, status vocabulary, workflow |
| `tools/amiga-sdk/registry.sh` | POSIX shell/awk validator, coverage generator, issue-body generator |
| `plans/amiga-sdk/00-index.md` | Programme map and bundle order |

## Capability schema

14 tab-separated columns; values contain no tabs:

```text
id  bundle  area  capability  priority  tier  min_os  min_hw  status  depends  acceptance  evidence  spec  notes
```

| Field | Allowed values / rule |
|---|---|
| `id` | `SDK-<AREA>-<NNN>`, unique, never reused |
| `bundle` | an id from `bundles.tsv` |
| `area` | library/device area, e.g. `graphics/bitmap` |
| `capability` | one capability, not one C function |
| `priority` | `must`, `should`, `could`, `wont` |
| `tier` | `core`, `advanced`, `optional` |
| `min_os` | `1.3`, `2.0`, `2.1`, `3.0`, `3.1`, `any` |
| `min_hw` | `OCS/68000/512K`, `ECS/68000/1M`, `AGA/68020/2M`, `any` |
| `status` | `missing`, `planned`, `in-progress`, `blocked`, `done`, `deferred`, `out-of-scope` |
| `depends` | comma-separated IDs, or `-` |
| `acceptance` | test/demo id, or `-` |
| `evidence` | commit/FS-UAE/checksum reference, or `-` |
| `spec` | appendix/section anchor, or `-` |
| `notes` | short constraint; no tabs |

## Validator rules

`registry.sh check` fails when:

- the header or column count is wrong;
- an ID is duplicated or malformed;
- `bundle` is not in `bundles.tsv`;
- `priority`, `tier`, `min_os`, `min_hw`, or `status` is outside the allowed set;
- a dependency does not exist;
- a `done` row has `acceptance` or `evidence` equal to `-`;
- a `must` row is `out-of-scope`.

`registry.sh coverage` writes `coverage.md` with one section per bundle and a
count table. `registry.sh issues` writes one issue body per bundle to
`build/amiga-sdk/issues/` with a checklist of the bundle's capabilities. The
`tracking_issue` column in `bundles.tsv` is filled after creation; the generator
rewrites every body, so the registry remains the source of truth.

## Issue workflow

- Create labels once: `amiga-sdk`, `bundle:<id>`, `tier:core`, `tier:advanced`,
  `priority:must`, `priority:should`, `good-first-issue`.
- Create one tracking issue per bundle with the generated body.
- Store the issue URL/number in `bundles.tsv`; regenerate the coverage view.
- At bundle start/end, regenerate the body; do not hand-edit checklists.
- Close a bundle's tracking issue when all its `must`/`should` rows are `done` or
  explicitly deferred.

## Seed scope

Bundle 0 seeds every bundle at capability level (about 6–10 rows per bundle). Each
bundle plan expands its own rows; the registry is not a complete NDK dump.

## Update policy

- A capability row is updated in the same commit as the implementation.
- `done` requires an acceptance test/demo and evidence.
- `coverage.md` is regenerated by `make sdk-registry`; a stale generated file is a
  review finding.
