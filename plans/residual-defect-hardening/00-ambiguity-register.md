### Resolution Notes

**AR-1:** Four phases: DEF-46 (literal type shape and deferred row store), DEF-47 (multi-extent return copy), DEF-48 (unguarded loop-condition release), DEF-49 (substitution-aware ownership), then a close-out phase.
**AR-2:** Suite names derive mechanically from the plan folder name, matching the repository's `<feature>_{spec,impl}_test.rs` convention.
**AR-3:** The challenger converged on canonicalization (High confidence). `iterated_element`, `type_key`, and `record_struct_type` already assume flat extents; the nested form is reachable only from no-context inference and already breaks conditional-literal typing.
**AR-4:** The challenger recommended the targeted pass and named the AST re-check as the durable alternative (Medium confidence). A cleanup-only fix is unsound because move-vs-copy is decided by the same substitution-blind predicate; the pass must re-derive drops and moves together. Superseded by AR #17, which replaced the pass with obligation records discharged per instance.
**AR-5:** The guarded path already drops the previous materialized value before re-storing it and releases the last value after the loop; the fix routes owned-call conditions into that path instead of inventing a new drop-in-expression form.
**AR-6:** RED-PHASE RULE: DEF-46 and DEF-47 fail by invalid C today, so their spec cases fail loudly; DEF-48 and DEF-49 are leak-only, so each gets a pre-fix AddressSanitizer probe recorded in the execution plan plus an emitted-shape implementation pin, mirroring the prior plan's handling of leak-only cases.
**AR-7:** The roadmap rows remain under `call-value-integrity` as their origin, with this plan linked at stage Plan Created.
**AR-8 to AR-12:** Presented together after the first seven decisions; the user confirmed all five recommendations explicitly (bulk acceptance of the recommended option on each row).
**AR-17 (reopened during authoring):** While specifying the DEF-49 pass, the suppression-site inventory showed all nine sites are genuinely unsafe under an owning substitution (guarded operands evaluate twice, aggregate stores copy an owned handle, take arguments are not emptied, iterables re-evaluate, moves are not recorded), and the move-vs-copy rewrite must detect later uses of a copied source to reject them — which is the checker's flow analysis. The `CopyObligation` record exists in `ir/mono.rs` but has no consumer yet, and the specification model is "record the obligations a generic body needs and discharge them at each instantiation". Reopened and re-decided: obligation records discharged per instance. Verified during authoring: `emit_drop` substitutes the place type (`compiler/src/codegen/drop.rs:23`), `emit_local_declarations` substitutes local and temporary types (`compiler/src/codegen/function.rs:237`, `:252`), and `ReleaseTemp` routes through `emit_drop` (`:518-526`), so a maybe-owning duty recorded once discharges correctly per instance with no per-instance body.

**Preflight correction (PF-002):** AR #3's note that the nested form "is reachable only from no-context inference" was wrong: generic substitution (`substitute`, `compiler/src/types/mod.rs:423-449`) builds nested fixed arrays directly, so folding `Ty::array` alone cannot prevent them. The approved fix folds in `substitute` as well. The parser flattens written multi-extent types, so `resolve_ty_with` cannot nest fixed arrays and stays unchanged.

**Preflight correction (PF-001, PF-009, PF-012):** the suppression-site inventory behind AR #17 was incomplete: the take-argument move/move-out pair (`own/call_check.rs:281`, `own/call.rs:352`) and the loan-owner predicate (`own/lower.rs:865`) were missing. The corrected table has fourteen sites across twelve rows and a site→case map in `07-testing-strategy.md`.
